## Notes on phase sequencing

- Phase 3 is a prerequisite for any phase that touches real PDL-scale data (4 onward, in practice, since scoring rules should be validated against real company-only records, not just synthetic ones). Phase 2 laid the schema groundwork (provenance/identity tables) but did not implement the importer itself.
- Phase 5 (seller/service profile) blocks Phase 6 in practice too — reviewing outreach drafts that pitch the wrong product isn't meaningful review.
- Phases 8 and 9 are the only phases that involve actual compute spend and must get explicit user go-ahead before launching, per the implementation contract's escalation rules.
- The disqualified-lead-reaches-Slack bug (D.2) was pulled forward into Phase 2 at the user's explicit instruction, ahead of the rest of Phase 11's routing/metrics work (concurrency idempotency, mock-vs-real dashboard breakdown), which remains sequenced at Phase 11. Phase 3 found and closed a second path to the same bug (blocked status erased by outreach review) before importing real data.
- Similarly, Part D of Phase 2 (output/review identity: `ai_output_id`-scoped approve/reject, stale-draft rejection, idempotent retries) was pulled forward ahead of the rest of Phase 6 (the actual annotation workflow, edit/correction UI, training-example export), at the user's explicit instruction that this was needed before real reviews could be trusted.
- Phase 3's Part E (CSV upload size/row caps, pagination on all list endpoints) was pulled forward from what would otherwise be Phase 12/10-adjacent hardening work, at the user's explicit instruction, specifically because 5,000 real PDL leads make the previously-cosmetic "unbounded list" issue (audit.md F.3) a real, user-visible problem the moment this phase's data lands.
- Phase 4 is accepted complete on the recorded Claude Code verification, as directed by the user on 2026-09-23 (§13 of the Phase 4 handoff). It deliberately scored the real cohort against the same two criteria (industry/country) that Phase 3's import already filtered on, so the real-cohort result (uniform 100/strong_match) validates the *scoring mechanism* end-to-end but provides no discriminating signal yet — Phase 5's seller profile is what will make future scoring runs actually differentiate leads. Phase 5's mechanism is implemented and verified, and its schema is applied to the real database. Scoring runs will only start to differentiate leads once actual seller content is supplied, reviewed, activated, and, for size, adopted in a new versioned rubric. Phase 6 has not started.
